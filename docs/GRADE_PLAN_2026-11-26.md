# 등급 기반 권한 전환 준비안 (미구현, 검토용)

근거: 사용자 WhatsApp 2026-11-26 14:06 (등급별 권한 정의), 14:07 ("등급 기준으로 바꾸자": 기존 그룹 지정을 등급으로 대체).
이 문서만 있고 코드·DB는 바뀌지 않았다. 노출 제한 단위/대상이 미정이라 운영에는 적용하지 않는다.

## 확정된 규칙
| 등급 | 일반 자료 생성·열람 | 보안 자료 생성·열람 | 노출 제한 |
|---|---|---|---|
| 0~2 | O | O | O |
| 3 | O | O | X |
| 4 (등급 미부여) | O | X | X |

등급 이름: 0 함장 / 1 항해사·전투원·상인 / 2 베테랑 탐사원 / 3 탐사원 / 4 그 외 전원.
관리자(site_role=admin)와 등급은 별개 필드.

## 기술 설계안
- `profiles.grade smallint not null default 4 check (grade between 0 and 4)`.
- 등급 근거는 Discord 역할 (기존 방향). `discord_role_grade_mappings(guild_id, discord_role_id, grade)` 신설, 관리 화면에서 연결.
  보유 역할 중 가장 높은 등급(작은 수)을 쓴다. 매 요청 즉시 재검증(fittings-api의 기존 방식), 확인 실패·탈퇴 시 4등급(fail-closed).
- `fittings.visibility`: `public`(= 일반 자료) / `security`(= 보안 자료)로 대체. 기존 `groups`와 `fitting_groups`는 읽기 전용으로 남기고 새 판단에는 쓰지 않는다. 현재 서버 피팅 0건이라 이관 대상 없음.
- 보이는 규칙(안): 일반 = 누구나, 보안 = 확인된 등급 0~3. 생성 규칙도 같은 함수로 서버에서 검사.
- 댓글·테스트 기록: 지금은 그룹 지정 피팅에만 붙는다. 보안 자료에 붙이는 걸로 옮기는 것이 자연스럽지만 사용자 확인 전이다.
- RLS: `fitting_is_visible`을 등급 함수로 교체. 관리자 전체 열람은 여전히 미결정이라 넣지 않는다.

## 사용자 확인이 필요한 것
1. 노출 제한: 누구의 자료를 누구에게서 가리는지, 자료 단위인지 등급 단위인지.
2. 실제 STAM Discord 역할 이름 (연결 전까지 등급 매핑은 비어 있고, 모두 4등급으로 시작한다).
3. 전환 시점에 함장(0등급)을 누가 어떤 역할로 갖는지 (시험 서버 역할로 먼저 시험 가능).
